## 3. 確認事項・バグの疑い

- 疑い 1：画面基本設計書 H09 は失敗の行の行動を「―」と定めているが、GenerationTable は action ?? "―" のため、失敗の行でも action に値があればそのまま出す（TC-UT_P207-017）。サーバーが失敗の生成イベントに action を入れなければ表には現れないので、影響は小さいと考える。
- 確認事項 2：画面基本設計書 H15 は「あり（N 件）」だが、一覧の API の GenerationItem は hasConsistencyFlags（真偽）だけで件数を持たない。今は「あり」とだけ出す（TC-UT_P207-019）。件数を出すなら API の変更が要る。
- 確認事項 3：実行 ID は設計書 6章の正規表現（Crockford Base32 の英大文字）で検査するため、英小文字で貼ると「実行 ID は 26 字です」になる（TC-UT_P207-009）。ULID は大小を区別しないので、大文字に直してから検査するかを確認したい。
- 確認事項 4：TC-NOUS71_DEV-11 は findByText("ミナト") を使うが、エージェントの選択肢（option）にも「ミナト」があるため、複数の要素に当たって失敗する可能性がある。DEV のテストは直さず、実施のときに結果を見る。UT では表のセル（role=cell）で探している。
- 確認事項 5：エージェントの選択肢の取得（GET /admin/api/agents）が失敗しても何も知らせず、選択肢が「すべて」だけになる（TC-UT_P207-029）。
