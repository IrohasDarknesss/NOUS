## 3. 確認事項・バグの疑い

- 確認事項 1：PUT /settings で running のまま新しい上限を超えたとき、running → limit_stopped は設定の更新とは別のトランザクション（コミットの後の enterLimitStopped）で行う。world.md 6章のトランザクション制御の表は updateSettings を「world_settings の更新、状態の変更、recordAudit」で1つとしている。NOUS-58 の決めたこと 4 として再鑑で認められているため疑いにはしないが、間に巡が始まる余地がある。設計書の表をどちらに合わせるかの確認
- 確認事項 2：GET /world・GET /settings は、現在の世界がないとき find と create を別に行う。同時に2回届くと、2回目の createInitialWorld が ux_worlds_current に当たって 500 になりうる（管理者は1人のため影響は小さい）。TC-UT_WLD-055 は順に2回呼んだときだけを見ている
- 確認事項 3：countAgentsByState の active・stopped 以外の state（settingsService.ts:185 の偽）、world_settings がないとき（settingsService.ts:212・270、worldRoutes.ts:119）、楽観の確認で 0 行（settingsService.ts:311）、enterLimitStopped の後に limit_stopped でない（settingsService.ts:333）は、CHECK 制約と同期のトランザクションのため単体テストでは起こせない。分岐の一覧からは外した
- 確認事項 4：resolveGenerationConfig の既定（config/generation.json を読んでキャッシュする）は、リポジトリのファイルに依存するため単体テストでは見ない。DEV と UT は configureWorldApi か generationConfig の引数で差し替えている
